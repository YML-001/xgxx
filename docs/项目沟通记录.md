## 一之二、流程调整：综合办统一受理 → 派发到科室成员（最新）

### 需求原文

> 学工信箱业务流程需要调整一下：学生发了信箱统一到综合办管理员，再由综合办管理员分发到各部门/科室的具体成员（派发的时候先选择科室再选成员），相关教师就能看到内容并处理；后台需要可以配置科室及科室成员。

### 与原流程的差异

| 环节 | 原流程 | 调整后 |
| --- | --- | --- |
| 学生提交 | 系统按事务类型**自动归口**到科室，直接进入「办理中」 | 统一送达**综合办公室**，进入新状态「**待分派**」 |
| 分派 | 无人工分派环节（管理员仅在特殊情况转办科室） | 综合办管理员在「待分派信件」中**先选科室、再选该科室成员**派发，支持批量派发与转派 |
| 承办主体 | 科室负责人（每科室 1 人） | 科室**具体成员（承办老师）**，一个科室可配多人 |
| 办理权限 | 科室负责人可办理本科室全部信件 | 科室教师可**查看**本科室全部承办信件，但**仅能答复派发给本人**的信件 |
| 事务→科室绑定 | 决定自动归口结果 | 降级为「**建议归口科室**」，仅在派发弹窗中预选，管理员可改派 |

### 关键实现决策

| 决策点 | 处理方式 |
| --- | --- |
| 是否保留事务→科室绑定 | 保留。改为派发时的**建议值**与「对口」标记，既保留既有配置价值，又不再强制归口 |
| 待分派信件的 `dept` 字段 | 置空字符串而非填「综合办公室」，避免污染各科室承办量统计；展示层统一走 `deptLabel()` 回退为「待分派」 |
| 科室成员数据结构 | `MOCK.sections[].members[]`，含 `id / name / title / phone / email / affairs / enabled`；`affairs` 用于派发时的「对口」优先排序 |
| 成员删除与停用 | 有承办记录的成员**不可删除**，只能「停用」；停用后不再出现在派发选择器，历史承办记录与统计保留 |
| 承办人快照 | 信件上存 `assignee` 快照（含姓名与岗位），成员改名时同步刷新已有信件，保证详情与统计口径一致 |
| 派发记录 | 每次派发/转派写入 `letter.dispatches[]`（时间、操作人、去向、原承办、说明），在详情「派发记录」与办理流程时间轴中呈现 |
| 时间轴时间单调性 | 真实派发/答复时间与按来信时间推导的节点混排时，用**单调时钟**取较大值，避免时间倒序 |
| 演示身份切换 | 「科室教师」顶栏改为**两级选择器（科室 → 本人）**，移动端「更多」页同步；真实系统应由登录账号确定承办人身份 |
| 催办送达对象 | 已派发 → 承办科室 + 承办人；未派发 → 综合办公室。催办模板新增 `{承办人}` 占位符 |
| 超期口径 | 「待分派」同样计入超期，督办页新增「**超期未派发**」指标，压实综合办的派发时效 |

### 涉及改动

- **数据层** `js/data.js`：新增 `STATUS` 状态枚举、`MOCK.intakeSection`、科室 `members`、`dispatchLetter()` / `dispatchItemsHtml()` / `membersForAffair()` / `getPendingLetters()` / `getMemberLetters()` 等；重写 `buildProcessLog()` 为「提交 → 综合办受理 → 派发承办 → 科室办理 → 答复反馈」五段式；配置键升至 `xg_config_v8`、播种标记升至 `xg_seeded_v6`。
- **桌面端** `js/app.js`：新增「待分派信件」页面（`#/dispatch`）与两步派发弹窗；办理弹窗按角色拆分为「综合办受理/督办」与「教师答复办结」；科室收件箱新增「我承办的 / 本科室全部」范围切换；科室管理页新增科室成员的增删改与启停用；统计分析新增「待分派」状态与「承办人办理绩效」。
- **移动端** `js/mobile.js`：新增「待分派」Tab 与派发抽屉（两步选择）；工作台改为承办人视角；「更多」页新增成员身份切换。
- **样式** `css/style.css`、`css/mobile.css`：新增派发记录、两步选择器、范围切换、办理流程条、承办老师列表等组件样式。
- **静态设计稿** `tools/build-pages.js` + `pages/`：新增 `admin-dispatch.html`（桌面 + 移动），角色文案与导航中心同步更新，共 52 页。

## 二、历史核心需求（原文）

> 学工信箱改动：
> 1. 只做**学工部各科室维度**的内容；
> 2. 增加**各科室负责人配置**，各科室负责人负责回复触达本科室的信件；
> 3. **管理员**能看到整个学工部的信件并能够**回复及催办**；
> 4. 后台管理缺少**制度文件、部门联系方式的管理及维护**；
> 5. PC 端调整好之后，**同步出一个移动端**。

### 需求拆解与关键决策

| 需求 | 实现决策 |
| --- | --- |
| 只做学工部各科室维度 | 移除「校长信箱 / 党委信箱」，仅保留**学工信箱**一个信箱；把校级各部门替换为**学工部 8 个内设科室**作为归口维度 |
| 各科室负责人配置 | 每个科室带 `head`（负责人）+ 电话 + 邮箱 + 职责 + 承接事务；在「科室管理」页维护 |
| 负责人回复本科室信件 | 新增 **`section` 角色**：只见并只能办理本科室归口信件（受理 / 答复办结 / 重开），不可跨科室转办、不可催办；并做**越权保护** |
| 管理员看全部 + 回复 + 催办 | 管理员可见全部科室信件，支持受理并分派、转办科室、答复办结、**督办提醒 / 催办** |
| 制度文件管理 | 新增「制度文件管理」页：增删改 + 现行有效/废止切换 |
| 部门联系方式管理 | 用「科室管理」页承载：维护负责人与联系方式；改名会同步事务绑定与历史信件归口 |
| 同步移动端 | 移动端学生功能同步为科室维度（单一信箱、归口科室提示、科室联系页） |

## 三、角色与权限模型

| 角色 | 职责 | 可见范围 | 可执行操作 |
| --- | --- | --- | --- |
| **学生** | 提交并跟踪诉求 | 本人信件 + 公开信件 | 写信、催办、撤回、补充、评价、二次办理 |
| **科室负责人** | 回复触达本科室的信件 | **仅本科室**归口信件 | 受理、答复并办结、重新打开（不可跨科室转办 / 催办） |
| **管理员** | 统筹全部诉求 | **学工部全部科室**信件 | 受理并分派、转办科室、答复办结、督办催办，以及分类 / 科室 / 制度文件配置维护 |

- 顶栏可切换身份；切到「科室负责人」时，顶栏出现**科室选择器**，用于演示不同科室负责人的视角。
- 越权保护：科室负责人打开非本科室信件时会被拦截提示「该信件不属于本科室」。

## 五、功能清单

### 学生来信端
- 工作台：Hero + 快捷入口 + 办理情况环形图 + 「13715」接诉即办承诺 + 最新公开信件。
- 写信须知：受理范围 / 不予受理清单 + 倒计时阅读。
- 我要写信：信件模板、**富文本编辑器**（加粗/斜体/下划线/列表/清除格式）、**AI 润色**（润色前后对照再应用）、**归口科室自动提示**、字数计数、附件模拟、重复来信校验、草稿保存。
- 我的信件：状态标签页 + 多条件搜索 + 详情弹窗（流程时间轴、答复、催办、撤回、补充材料、满意度评价、二次办理）。
- 信件查询、公开信件、制度文件、数据统计（各科室来信量、办理绩效）。
- **科室联系方式**（含负责人 / 电话 / 邮箱 / 职责 / 承接事务）、常见问题。

### 科室负责人端
- 科室工作台：**仅本科室**统计（待受理 / 办理中 / 已办结 / 超期）+ 本科室待办 + 办理情况环形图。
- 科室收件箱：本科室归口信件，状态标签页 + 按标题/分类/事务筛选。
- 信件办理（本科室）：受理并办理、答复并办结、重新打开；归口锁定本科室。

### 管理员后台
- 办理工作台、信件收件箱（全部科室）。
- 信件办理（管理员）：受理并分派、转办科室、设时限/紧急程度、督办提醒、答复办结。
- 督办催办、来信选登管理、统计分析（各科室办理绩效 + 满意度）。
- 分类管理：信件分类（名称+标识色）、事务分类 + **绑定归口科室**。
- **科室管理**：维护科室负责人 / 电话 / 邮箱 / 职责（即部门联系方式的管理维护）；绑定事务或有信件的科室禁止删除，改名同步绑定与历史信件。
- **制度文件管理**：增删改 + 现行有效/废止切换，学生端同步展示。

### 移动端（学生专属）
- 手机外壳（AppBar + TabBar + 悬浮写信 + 底部抽屉），单一学工信箱、无信箱切换。
- 页面：首页、写信须知、写信（模板+富文本+AI 润色+归口科室提示）、我的信件、公开信件、信件查询、制度文件、数据统计、**科室联系**、常见问题、更多（含前往桌面端后台链接）。

### 业务闭环
学生提交 → 管理员受理分派 / 归口科室受理 → 科室负责人办理答复办结、管理员督办催办 → 学生查看进度与答复 → 满意度评价 / 二次办理。全流程由 `localStorage` 驱动，可在三种身份、两个终端间来回验证。

## 六、技术要点

- **纯前端**：HTML + CSS + 原生 JS，无构建、无依赖、无后端与鉴权。
- **路由**：桌面端 hash 路由 SPA；移动端内部状态路由。
- **数据层共享**：桌面端与移动端共用 `js/data.js` + `localStorage`，数据实时同步。
- **持久化**：信件、角色、当前科室，以及分类 / 事务 / 科室 / 制度文件配置全部存 `localStorage`；版本号升级后旧数据自动重置为新演示数据。
- **图表**：原生 Canvas 手绘环形图 / 条形图。
- **富文本**：`contenteditable` + 工具栏；`stripHtml` / `contentHtml` 负责纯文本与安全展示的转换。
- **AI 润色**：前端模拟，提供润色前后对照。
- **设计语言**：靛蓝渐变侧边栏 + 青蓝强调色 + 卡片式浅色主题；响应式 + 无障碍（`aria-label`、`<output>` toast）。

## 七、关键问题与修复

| 问题 | 原因 | 修复 |
| --- | --- | --- |
| 页面白屏 | `getElementById(...)?.onclick = ...` 造成 `Invalid left-hand side in assignment` | 改为先取元素判空再绑定事件 |
| jsdom 安装报 `ERR_REQUIRE_ESM` | 新版 jsdom 不兼容 Node 18 的 require | 降级 `jsdom@22` |
| 冒烟测试 `App not defined` | `runScripts: outside-only` 下 `const` 不挂到 window | 合并脚本到同一 `eval` 并显式挂到 `window` |
| 冒烟测试 `scrollTo / canvas` 报错 | jsdom 未实现浏览器 API | stub `window.scrollTo` 与 Canvas `getContext`（含 `arcTo` 等） |
| 移动端 viewport 无障碍告警 | `user-scalable=no` | 移除该限制，允许缩放 |

## 十、运行方式

无需任何构建工具或依赖，浏览器直接打开（推荐 Chrome / Edge）：

```
双击 index.html    # 桌面端（学生 / 科室教师 / 综合办管理员，顶栏切换身份与承办人）
双击 mobile.html   # 移动端（三角色，「更多」页切换）
```

如需恢复初始演示数据：清除站点 `localStorage` 后刷新即可。
