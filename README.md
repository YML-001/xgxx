# 学工信箱系统原型（Student Affairs Mailbox）

面向高校 **学生工作部（学工部）** 的「学工信箱」交互原型。围绕「倾听学生声音、畅通诉求渠道、接诉即办、件件有回音」的主题，采用 **「综合办统一受理 → 派发到科室具体成员承办」** 的业务流程，覆盖 **学生来信端**、**科室教师端** 与 **综合办管理员后台** 三套视角。纯前端实现（HTML / CSS / 原生 JavaScript + ECharts + localStorage），**无需任何构建工具或后端**，双击 HTML 即可运行。

> 演示性质的高保真原型：所有数据存放在浏览器 `localStorage`，通知推送、附件下载等对接项均为前端模拟（详见文末「原型局限 / 待对接」）。

## 快速开始 / 在线预览

无需 `npm install`、无需构建，直接用浏览器打开（推荐 Chrome / Edge）：

| 入口 | 说明 |
| --- | --- |
| **`pages/index.html`** | **推荐从这里开始** —— 页面导航中心，罗列全部静态设计稿页面（桌面端 29 页 + 移动端 23 页），并内置「演示入口」直达可交互的实时应用。 |
| `index.html`（根） | 桌面端 **实时 PC 应用**（单页应用，可真实交互：写信、办理、配置、统计等）。 |
| `mobile.html`（根） | 移动端 **实时 H5 应用**（手机视角，支持 `?role=student\|section\|admin` 直达对应角色）。 |

桌面端与移动端 **共享同一套数据层**（`js/data.js` + `localStorage`）：学生在移动端提交的信件，先由桌面端综合办管理员派发到科室承办老师，承办老师答复办结，学生再回到移动端查看进度与答复，形成闭环。

> 恢复初始演示数据：清除本站点的 `localStorage` 后刷新页面即可重新播种。

### `pages/` 是自包含的，可单独部署

`pages/` 目录经 `tools/build-pages.js` 生成后 **完全自包含**：运行时资源（css/js/vendor）会被复制进 `pages/assets/`，并在 `pages/` 内生成实时应用副本 `app.html`（PC）与 `mobile.html`（移动）。因此 **只上传 `pages/` 一个文件夹**（例如部署到 GitHub Pages）即可完整预览：导航中心 + 实时 PC 应用 + 实时移动应用 + 全部静态快照，无任何外部依赖或断链。

- 本地：直接双击 `pages/index.html`。
- GitHub Pages：仓库设置 Pages 后，导航中心地址形如
  `https://<用户名>.github.io/<仓库名>/pages/`
  （若把 `pages/` 作为站点根目录发布，则为 `https://<用户名>.github.io/<仓库名>/`）。

> 根目录仍是唯一「源」；`pages/assets/` 与 `pages/app.html`、`pages/mobile.html` 均由生成器自动同步，请勿手工编辑，改动 `css/`、`js/` 后重新执行 `node tools/build-pages.js` 即可。

## 技术栈

- **纯前端**：HTML5 + CSS3 + 原生 JavaScript（无框架、无打包器）。
- **单页应用**：hash 路由（`#/route`），按角色渲染侧边栏与页面。
- **图表**：[ECharts 5](https://echarts.apache.org/) —— 本地引入 `vendor/echarts.min.js`（**已随仓库提交，离线可用**，无需 CDN）；管理员「统计分析」使用折线 / 柱状 / 饼图，其余小图使用原生 Canvas。
- **数据持久化**：浏览器 `localStorage`（信件、配置、FAQ 等）。
- **设计语言**：中南蓝（`#3087CC`）主题，左侧边栏 + 顶栏 + 卡片式内容区，线性 SVG 图标（非 emoji）。
- **页面生成器**：`tools/build-pages.js`（Node 脚本）把 SPA 各可达页面「快照」为独立静态 HTML，便于逐页设计评审。

## 角色与页面导航

顶栏（桌面）/「更多」页（移动）可切换身份。切换为「科室教师」时，顶栏出现 **两级选择器（科室 → 本人）**，用于演示不同科室、不同承办老师的视角（各自仅能答复派发给本人的信件）。

| 角色 | 职责 | 可见范围 | 主要页面 |
| --- | --- | --- | --- |
| **学生** | 提交并跟踪诉求 | 本人信件 + 公开信息 | 工作台、我要写信、我的信件、信件查询、公开信件、制度文件、数据统计、科室联系方式、常见问题 |
| **科室教师** | 办理 **派发给本人** 的信件 | 本科室全部承办信件（仅本人承办件可答复） | 我的工作台、科室收件箱（我承办的 / 本科室全部）、公开信件、制度文件 |
| **综合办管理员** | 统一受理、派发、督办与后台配置 | **全部**信件 | 办理工作台、**待分派信件**、信件收件箱、督办催办、来信选登管理、统计分析、分类管理、科室管理（含科室成员）、制度文件管理、超期与催办配置、常见问题配置 |

### 核心业务闭环

- **来信办理**：学生写信 → 统一送达 **综合办公室** 受理（状态 **待分派**）→ 综合办管理员 **先选科室、再选该科室成员** 派发（状态转 **办理中**）→ 承办老师核实办理、答复并办结 → 学生查看答复 → **满意度评价**（星级 + 标签 + 文字）→ 不满意可 **申请二次办理**。
- **派发与转派**：待分派清单支持单封派发与 **批量派发**；派发弹窗按事务预选「建议归口科室」并标注「对口」成员，同时展示各科室成员的在办量以便均衡分配；已派发信件可 **转派** 给其他科室或成员，全过程写入 **派发记录**，在信件详情与时间轴可见。
- **权限边界**：科室教师可查看本科室全部承办信件（用于协同），但 **仅能答复派发给本人的信件**；未派发信件对科室不可见，仍在综合办受理中。
- **草稿 / 撤回 / 补充**：可存草稿并再编辑、提交或删除；办理中信件可撤回；可提交 **补充材料**（文字 + 附件），在详情时间线与科室办理端可见。
- **催办**：学生催办 / 管理员批量催办，按 **可配置模板** 生成催办内容并通过 **系统消息 / ITS** 渠道「送达」；已派发件送达 **承办科室与承办人**，未派发件送达 **综合办公室**，催办记录在详情与办理端可见。
- **督办**：超期信件自动标记并进入督办清单，其中「超期未派发」单独计数，提醒综合办尽快派发。
- **信息公开**：管理员「来信选登管理」将已办结信件选登公开，学生端「公开信件」可查看。

## 配置项说明（管理员）

后台「配置」分组的页面保存后 **实时驱动前台**：

- **超期与催办配置**（`超期与催办配置`）
  - `超期天数`：来信超过 N 天未办结即标记「超期」并纳入督办（默认 **7** 天）。
  - `催办消息模板`：支持占位符 `{科室}` `{姓名}` `{事务分类}` `{标题}` `{编号}` `{来信时间}` `{已过天数}` `{催办时间}`。
  - `默认发送渠道`：系统消息 / ITS（可多选）。
- **常见问题配置**：FAQ 全量增删改、启用/停用、上移下移排序；学生端（桌面 + 移动）按 **启用 + 排序** 实时展示。
- **分类管理**：信件分类（一级）、事务分类（二级）及事务→**建议归口科室**绑定（派发时预选，管理员仍可改派）。
- **科室管理**：科室及负责人 / 联系方式 / 承接事务，以及 **科室成员（承办老师）** 的增删改与启停用 —— 成员即派发时可选的承办人；停用成员不再出现在派发选择器中，历史承办记录保留。
- **制度文件管理**：制度文件富文本正文 + 附件的增删改。

## 重新生成 Word 文档

`docs/*.docx` 均由 `tools/` 下的 Python 脚本生成，**请勿手工编辑 docx**——改内容后重跑脚本即可。
其中《PRD》以 `docs/PRD.md` 为唯一事实源，改需求只需改 Markdown。

```bash
pip install python-docx            # 仅首次

python3 tools/gen-prd-docx.py                 # docs/PRD.md → 学工信箱PRD.docx
python3 tools/gen-feature-intro-docx.py       # → 学工信箱功能介绍.docx
python3 tools/gen-notify-docx.py              # → 学工信箱消息提醒与模板.docx
python3 tools/gen-feature-workload-docx.py    # → 学工信箱功能清单与工作量评估.docx
```

> 四个脚本共用 `tools/docx_kit.py` 的排版工具（字体、表格、页眉页脚、目录域），版式统一；调整版式只需改这一处。

> 静态页面为「冻结快照」（不加载 `js/app.js`），图表以占位框呈现，仅用于逐页设计评审；真实交互请使用 `index.html` / `mobile.html`。

## 原型局限 / 待对接

本项目为 **纯前端演示原型**，以下能力为模拟实现，接入真实系统时需替换：

- **通知推送**：催办「系统消息 / ITS」为前端记录 + 提示，未接入真实消息通道；暂无独立的「消息 / 通知中心」页面（催办记录已在信件详情与办理端可见）。
- **附件上传 / 下载**：上传与预览基于浏览器内存（图片可预览），下载为占位提示，未接入对象存储。
- **数据持久化**：仅存于浏览器 `localStorage`，非多端 / 多用户后端；清缓存即重置。
- **鉴权**：角色切换为演示用途，无真实登录与权限校验。
- **派发通知**：派发后向承办老师的提醒为前端记录（派发记录 + 提示），未接入真实消息通道。
- **鉴权与承办人身份**：科室教师的「本人」身份通过顶栏选择器演示切换，真实系统应由登录账号确定，并据此限定可答复范围。
